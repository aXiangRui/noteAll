## 0. 全景：四步

```
        text = "上周三下午和小李讨论了方案"
        base = 2026-10-08 14:00  (周四)
                    │
                    ▼
    ┌───────────────────────────────┐
    │ ① 定位                         │
    │   从第 0 个字节开始找           │
    │   （只从开头找，不在中间找）     │
    └───────────────────────────────┘
                    │
                    ▼
    ┌───────────────────────────────┐
    │ ② 匹配                         │
    │   拿规则表逐条试               │
    │   「前缀 + 主体 + 后缀」        │
    │   能吃多长就吃多长              │
    └───────────────────────────────┘
                    │
         ┌──────────┴──────────┐
         ▼                     ▼
     ✅ 命中                  ❌ 全都没中
         │                     │
         ▼                     ▼
┌─────────────────┐   ┌──────────────────┐
│ ③ 归一化         │   │ occurred  = 空     │
│   算成具体时间    │   │ remainder = 原文   │
└─────────────────┘   └──────────────────┘
         │                     │
         ▼                     │
┌─────────────────┐            │
│ ④ 抠掉           │            │
│   从原文里切掉    │            │
└─────────────────┘            │
         │                     │
         └──────────┬──────────┘
                    ▼
        ParseResult { occurred, remainder }
```

**一句话**：开头开始 → 逐段啃 → 各段换算 → 切掉。

## 1. 接口

```cpp
// include/parse/timeParse.hpp        ← 实际文件名（不是 parse.hpp）

namespace parse {

struct ParseResult
{
    std::optional<core::TimeRange> occurred;   // 解析出的时间；空 = 没解析出来
    std::string                    remainder;  // 抠掉时间词后剩下的文本
};

ParseResult parseTime(std::string_view text, std::chrono::sys_seconds base);

}  // namespace parse
```

### 为什么 `base` 必须是参数

`base` 是**基准时刻**。"上周三"相对的是谁？就是这个 `base`。

**绝对不要在函数内部调 `now()`。** 理由：

```cpp
// ❌ 内部取 now()：测试没法写
parseTime("上周三");
//    ↑ 半夜跑测试会随机挂 —— 跨了一天，"上周三"就变了

// ✅ base 当参数：结果完全可预测
parseTime("上周三", 2026y/10/8d);
```

测试时传固定值，跑一万遍结果一样。这条对应 [DESIGN.md §8.4](DESIGN.md)。

## 2. 第 ① 步：定位

**只从开头（第 0 字节）开始匹配。**

```
"上周三下午和小李讨论了方案"     ← 时间在开头 ✅ 处理
"和小李上周三讨论了方案"         ← 时间在中间 ❌ 先不管
```

| | 只匹配开头 | 匹配任意位置 |
|---|---|---|
| 抠掉怎么做 | `substr(15)` 一刀切 | 前半段 + 后半段拼接 |
| 出错风险 | 低 | 抠错了原文就被吃坏 |
| 够用吗 | **够**——记笔记天然把时间写最前 | — |

以后真需要中间的时间，再改。**M1 不做。**

## 3. 第 ② 步：匹配

### 3.1 核心动作：一段一段往后啃

```
原文：  上  周  三  下  午  和  小  李 ...
        └─┬─┘
     第1轮：试「前缀」
     "上" 在前缀词表里？           ✅  记下 prefix="上"

原文：  上  周  三  下  午  和  小  李 ...
            └─┬─┘
     第2轮：试「主体」
     "周三" 是「周X」？            ✅  记下 body="周三"

原文：  上  周  三  下  午  和  小  李 ...
                    └─┬─┘
     第3轮：试「后缀」
     "下午" 在后缀词表里？          ✅  记下 suffix="下午"

原文：  上  周  三  下  午  和  小  李 ...
                        └─┬─┘
     第4轮：还能吃吗？
     "和" 在词表里？               ❌  停！
────────────────────────────────────────────
命中区间：  [0, 15 字节)  = "上周三下午"
拆出来的：  prefix="上"  body="周三"  suffix="下午"
```

**匹配不是"一眼认出整句"，是"一段段往后啃，啃不动就停"。**

> ⚠️ **现状与这张示意图的差别**（别照着图去找代码）：
> 实现里最终是**两段**，不是三段 —— `matchDate()`（主体：日期）+ `matchClockRange()`（后缀：时刻），
> 各算各的，最后在 `parseTime()` 里合并。
> 「前缀」不是独立的一轮，而是**主体内部的一部分**：`matchWeekDay()` 直接匹配「前缀 + 单位字 + 星期字」
> 这个复合形状，`matchMonthStart()` 同理匹配「前缀 + [个] + 月初」。
> 后缀那一侧则允许「[时段词] + [钟点] + [到|至 + [时段词] + 钟点]」。

### 3.2 顺序：长的优先

```
"上周三"   ← 先试（3 个字）
"上周"     ← 再试（2 个字）
"上"       ← 最后试（1 个字）
```

**短的先试会把长的截胡。必须先长后短。**

> 实现里没有"按长度排序再匹配"这一步，靠的是两条：
> ① 词表内部**不出现互为前缀的条目**（`大后天` 与 `后天` 靠 `starts_with` 天然不冲突）；
> ② 形状**按固定优先级依次尝试**（见 §3.5 表格自上而下）。
> 想加新词时，先检查它会不会和已有的词互为前缀 —— 那才需要显式排序。

### 3.3 词表（现状：7 张表，其中 2 张是死的）

词表全在 [include/parse/timeParse.hpp](../include/parse/timeParse.hpp)，不在 .cpp 里。

```
frontWords    │  上  下  这  本  前  后  昨  今  明  去          （前缀，10 个）
weekUnits     │  周  星期  礼拜                                  （「周X」只认这三个）
weekdayWords  │  一 二 三 四 五 六 日 天                         （8 个，「天」＝周日）
simpleWords   │  今天 昨天 明天 后天 前天 大后天 大前天 昨晚       （整词，带天数偏移）
yearWords     │  去年  今年  明年                                （相对年）
backWords     │  早上 上午 中午 下午 晚上 凌晨                    （时段词 + 代表时刻）
```

**两张已声明但当前无人引用的表**（改代码时别以为它们生效）：

| 表 | 内容 | 状态 |
|---|---|---|
| `unitWords` | 周 星期 礼拜 **月 年 天 日** | ❌ 死表。weekUnits 是从它里面切出来的三个；另外四个绝不能进「周X」匹配（`下月一号` 会被读成「下周的周一」） |
| `timeWords` | `0点` … `24点` 共 25 条 | ❌ 死表。实现走的是数字扫描（因为 `15:30` / `下午3点` 都得扫数字） |

> `unitWords` 留着还有点"反面教材"的作用（注释解释了为什么不能用它），
> `timeWords` 是纯粹的残留。要不要删是你的决定，**但文档必须说清它们没生效**。

（中文数字**钟点**已支持：三点 / 十点半 / 十点十五分；日期里的中文数字仍未支持。）

### 3.4 规则怎么组合

```
[前缀] + 周X        →   上周三 / 下周一 / 这周五
[前缀] + N月N日      →   3月5日 / 10月1日
整个词直接查表        →   今天 / 昨天 / 明天
主体 + [后缀]        →   上周三下午
```

**一条规则管一种说法。想支持新说法？加一条。**

### 3.5 现状速查：现在到底能解析什么

> 基准一律写死为 `2026-10-08 14:00`（**周四**），跟测试里的 `BASE` 一致。
> 这一节是对着实现和实测输出逐条核过的；跟 §3.1–§3.4 的示意例子有出入时，以本节为准。

#### 主体（日期），按优先级从上到下

| 形状 | 例子 | 结果 |
|---|---|---|
| 整词 | 今天 / 昨天 / 明天 / 后天 / 前天 / **大前天 / 大后天** | 10-08 / 10-07 / 10-09 / 10-10 / 10-06 / 10-05 / 10-11 |
| 整词（自带时段） | 昨晚 | 10-07 **20:00** |
| 前缀 + 周X | 上周一 / 本周一 / 这周五 / 下周三 | 09-28 / 10-05 / 10-09 / 10-14 |
| 前缀 + 周末 | 上周末 / 这周末 / 下周末 | 10-03 / 10-10 / 10-17 |
| **前缀叠两次** | 下下周三 / 上上周三 | 10-21 / 09-23 |
| 裸周X | 周四 / 周五 / 周一 | 10-08（今天取今天）/ 10-09 / 10-12 |
| 裸周末 | 周末 | 10-10 |
| 绝对日期 | 2026-10-01、2026-10-1、2026年10月1日、3月5日、3月5号 | 照写 |
| 无年份的月日 | 10月20日 / 10月1日 / 3月5日 / 2月29日 | 10-20 / **2027**-10-01 / **2027**-03-05 / **2028**-02-29 |
| **年前缀 + 月日** | 今年3月5日 / 明年3月5日 | 2026-03-05 / 2027-03-05（写了年份就照写） |
| 月初 | 这个月初 / 上个月初 / 下个月初 / 下月初 | 10-01 / 09-01 / 11-01 / 11-01 |
| **年整词** | 今年 / 明年 / 去年 | 2026-01-01 / 2027-01-01 / 2025-01-01 |

三条容易记错的规则：

1. **「还没到的那个」**：目标日期早于基准日就取下一次。`周一` → 10-12；`10月1日` → 2027-10-01；
   `周四`（今天）→ 10-08，判断用 `<` 不是 `<=`。
2. **`floorDay`（只用于区间第二个日期）**：`周一到周五` 里周五不许早于周一，否则区间倒过来（→ 10-16）。
3. **前缀只叠 `上`/`下` 两次**：`这这周三` 不成话，整句不认。

周日的写法：`周日` = `星期日` = `星期天` = `周天` = `礼拜天`。
⚠️ `天` 与 `天气` 撞头，`下周天气不错` 被专门挡掉，**整句不认**。

#### 后缀（时刻）

| 项 | 内容 |
|---|---|
| 时段词单独出现 | 早上 08:00 / 上午 09:00 / 中午 12:00 / 下午 14:00 / 晚上 20:00 / 凌晨 05:00 |
| 钟点写法 | `15点` / `9点半` / `15点30分` / `9:05` / `12:5`（分钟补零） |
| 分钟可省「分」 | `5点40` / `五点四十` / `23点50` / `十点零五分` |
| 一刻 / 三刻 | `十点一刻` → 10:15 / `十点三刻` → 10:45 |
| 中文数字钟点 | `三点` / `十点半` / `十点十五分` / `十一点` / `两点`（`两`=`二`，上限 59） |
| 时段词 + 钟点 | **`X点` 和 `X:XX` 两种写法都吃修正**：`下午3点` 和 `下午3:30` 规则一致 |

**12 点 / 0 点的边界**（不能按"小于 12 就 +12"一把梭）：

| 时段词 | 小时 < 12 | 小时 = 12 | 小时 = 0 |
|---|---|---|---|
| 中午 / 下午 | +12 | 12:00 | +12 |
| 晚上 | +12 | **次日 00:00** | 00:00 |
| 凌晨 | 照字面 | **00:00**（当天） | 00:00 |
| 早上 / 上午 / 没写 | 照字面 | 12:00 | 00:00 |

**区间**（分隔符 `到` / `至`）：

- 第二个钟点**自己写了时段词就用自己写的**：`晚上11点到凌晨1点` → 23:00 → 次日 01:00
- **没写就沿用**：`下午3点到5点` → 15:00 → **17:00**
- ⚠️ 沿用会把终点推到起点之前时**改按字面读**：`晚上11点到1点` → 23:00 → 次日 **01:00**（不是 13:00）
- 跨天：终点早于起点 → +1 天；终点**等于**起点 → 原样保留（不补成 24 小时）
- **日期区间**：`3月5日到3月7日`、`周一到周五`、`这周六到周日` → 一条连续跨度，
  `end` = 第二个日期**次日零点**（含第二个日期整天）。`周一到周五` → 周一 00:00 → **周六** 00:00
- **日期区间 + 钟点**：统一成一条跨度 —— 起点 = **首日 00:00**（钟点起点不参与），
  终点 = **末日 + 钟点终点**（只写钟点起点就用它）。`周一到周五下午3点到5点` → 周一 00:00 → 周五 17:00；
  `周一到周五下午3点` → 周一 00:00 → 周五 15:00
- ⚠️ 语义二重性：「周一到周五下午3点到5点」也可能指"每天 15:00–17:00"。`TimeRange`
  表达不了重复，**统一按一条跨度处理**，重复语义留给以后的数据模型
- ⚠️ 第二个日期仍早于第一个（`明天到昨天`）→ **整段区间不吃**，`到昨天` 留在 `remainder`。
  **绝不产出 `end < start` 的 TimeRange。**

#### 明确不支持（一律留空，不猜）

日期里的中文数字（二十号 / 三月五号）、**N 天前**（三天前 / 3天后）、`24点`、
整月（下个月 / 月底 / 3月 / 2026年10月）、`今年10月`（缺日）、周期（每天 / 每周）、
ISO 时间里的 `T09:00`、缩略词（今晚 / 明早）、`下下周`（后面没周X）、
**空格截断**（`明天 下午 3 点` 只认出日期）。

> 最后一条接 CLI 时会咬人：`main.cpp` 的 `add` 是用空格拼 `argv[2..]` 的，
> 所以 `note add 明天 下午3点` 传进来是带空格的，后缀解析不出来。见 §12。

## 4. 第 ③ 步：归一化

**三段各算各的，最后合并。**

```
base = 2026-10-08（周四）
        │
        ├─ body   "周三"  →  定位到"星期三"
        │                   本周三 = 10-07
        │
        ├─ prefix "上"    →  再往前推一周
        │                   上周三 = 09-30       ← 10-07 减 7 天
        │
        └─ suffix "下午"  →  时刻 = 14:00
        │
        ▼
   合并 = 2026-09-30 14:00
```

**每段只负责一件事** —— 哪段算错了，一眼看得出来。

### chrono 速查（只列原语，组合自己想）

| 你要做的 | 用这个 |
|---|---|
| 某年某月某日 | `std::chrono::year_month_day`，字面量 `2026y/10/1d` |
| 转到"天数"做加减 | `std::chrono::sys_days` |
| 加／减天数 | `+ std::chrono::days{7}` / `- std::chrono::days{7}` |
| 加／减月、年 | `std::chrono::months{1}` / `std::chrono::years{1}` |
| 判星期几 | `std::chrono::weekday` |
| "最后一个周X" | `std::chrono::weekday_last` |
| "第 n 个周X" | `std::chrono::weekday_indexed` |
| 当前是谁 | `std::chrono::weekday{sys_days{...}}` |

> **提示**：`base` 是 `sys_seconds`。要拿它当"某一天"用，
> 先转 `sys_days`（`std::chrono::floor<std::chrono::days>(base)`），
> 算完再转回来拼上时刻。

## 5. 第 ④ 步：抠掉 ⚠️ 中文的坑

```
原文：  上周三下午 | 和小李讨论了方案
         └── 15 字节 ──┘└── 剩下的 ──┘

remainder = text.substr(15)      ← 从第 15 字节切到尾
```

### ⚠️ 是**字节数**，不是字数

`std::string` 存的是**字节**。中文 UTF-8 一个字占 **3 字节**。

```
"上周三下午"   看起来 5 个字
              实际 5 × 3 = 15 字节

text.substr(0, 5)   ❌ 切出 1 个半字 → 乱码
text.substr(0, 15)  ✅ 完整的"上周三下午"
```

**匹配时记住"吃了多少字节"，抠的时候就切多少字节。**

（`std::string_view::size()` 给的也是字节数，正好。）

### 硬要求

> `remainder` 必须能还原出原文 —— **如果时间词抠错了，宁可不动文本。**

宁可 `occurred` 为空、`remainder` = 原文，也不要抠错。
（见 [ROADMAP.md §3](ROADMAP.md) 的硬要求）

> ⚠️ 这条在实现里有个具体体现：`pointHit()` 必须用**含时段词的 `pos`** 当长度，
> 用 `first->length_` 会漏掉「下午」那 6 个字节，`remainder` 就会多出一截
> （`下午3点` 变成剩 `3点`）。这是已经踩过并有用例盯住的坑。

## 8. 论文记号对照（广东工业大学那篇）

那篇的数学符号看着唬人，**其实是速记**。对照表：

| 论文符号 | 真正的意思 |
|---|---|
| `G = {Y, M, D, H, Mi, S}` | 六个时间刻度：年月日时分秒 |
| `G_D` | **"天"这个单位** |
| `-1G_D` | 减 1 天 → **昨天** |
| `-9G_D` | 减 9 天 → **9 天前** |
| `08G_M15G_D` | **8 月 15 日** |
| `t` | **基准时刻** ← 就是你的 `base` |
| `Δt` | 偏移量（"多少"天） |

### 论文的"定义 1（相对时态跨度）"在说什么

白话就一句：

> **"三天前" = 方向(前/后) + 数量(3) + 单位(天)，挂在 `base` 上算出来。**

记号 `(-|+)Δt_s^{G_i}` 拆开：

```
(-|+)   Δt_s    ^{G_i}
  ↓       ↓       ↓
方向     数量     单位
 -       3       天        →  三天前
```

论文那句 **"独立于任何时间粒点"** 的意思就是：**"三天前"自己不指明是哪一天，必须挂 `base`。**

**这正是你的 `base` 参数存在的理由。**

### 那篇真正值得抄的

跳过所有公式，只看这几样：

- 中文分四类：**时间粒点 / 时态粒区 / 相对跨度粒点 / 相对跨度粒区**
- 三张词表：**前缀词、后缀词、节日词**
- 用**正则 + Trie 树**做识别

## 11. 已知取舍（有意为之，不是 bug）

| 取舍 | 现状 | 备注 |
|---|---|---|
| 光写「今年」 | = 当年 1 月 1 日**一个点**，不填 `end` | 整年是个区间，先按「月初」的路数只给点 |
| `10月7日`（base 10-08） | → **2027**-10-07 | 「还没到的那个」规则的必然结果 |
| 周日当天说「这周末」 | → 前一天（周六） | 裸写 `周末` 会跳到下周六 |
| 日期区间 | **含末日整天**（到次日零点） | `周一到周五` → 周六 00:00 |
| `9点到8点` | → 次日 08:00（跨度 23 小时） | 规则统一，不判非法 |
| 日期区间 + 钟点 | 一条连续跨度：首日 00:00 → 末日 + 钟点终点 | `周一到周五下午3点到5点` 的"每天重复"表达不了，先按跨度收 |

> 这几条都可以改，但**改之前先把用例写好** —— 它们是"规则"，不是"错"。

## 12. ⚠️ 还没接进 CLI

`parse::parseTime` 已经接进 `note add`（2026-10-18）：`main.cpp` 先定
`created_at`，用它的本地墙上时间当 `base` 解析，结果换回 UTC 后写入 `occurred`。
`note show` 能看到解析结果；解析不出来就留空，`raw_text` 一个字不动。

接线时踩过、现在已处理的三个点：

1. **空格**：`main.cpp` 的 `add` 是用空格拼 `argv[2..]` 的，
   所以 `note add 明天 下午3点` 传进来是带空格的文本。解析器现在允许
   主体与后缀之间、「到」两边有空格（`skipSpaces`），跳过的空格算进被吃掉的区间。
2. **base 传谁**：相对的是 `created_at`，不是"现在的时刻"；补记场景下两者不同。
   所以 `created_at` 由 `main` 先定好传进 `core::add`，不让 core 自己取 `now()`。
3. **时区**：`parseTime` 算的是墙上时钟，`occurred` 要存 UTC。
   CLI 层用 `utcToLocalWall` / `localWallToUtc` 在解析前后各转一次。
   不转的话，UTC+8 机器上「今天」会变成昨天、「下午3点」会显示成晚上11点。
