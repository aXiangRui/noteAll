# 配置：数据在哪、key 放哪

这个程序没有配置界面、没有注册表设置项。所有"配置"就是两样东西：**数据文件**和**API key**。

## 1. 数据文件

| 项 | 规则 |
|---|---|
| 环境变量 | `NOTE_FILE` |
| 默认值 | 当前目录下的 `notes.jsonl` |
| 旁边会有 | `notes.jsonl.lock`（锁，常驻，别删）、`notes.jsonl.log`（出异常才有） |

> 「当前目录」不等于「exe 所在目录」：
> 终端里 `cd E:\project\cpp_workflow_demo` 后跑，数据在项目根；
> 双击 `dist\note.exe`，数据在 `dist\`。
> 交互模式启动时第一行会打印真实路径。

固定到文档目录（推荐，顺便被 OneDrive 备份）：

```powershell
[Environment]::SetEnvironmentVariable('NOTE_FILE', "$env:USERPROFILE\Documents\notes.jsonl", 'User')
```

## 2. API key（`note draft` 用）

按顺序找，**第一个找到的生效**：

| 顺序 | 位置 | 说明 |
|---|---|---|
| 1 | 环境变量 `NOTE_LLM_KEY` | 优先级最高，适合临时换 key |
| 2 | `<数据文件目录>\note.key` | 最推荐的放法：跟着数据走，拷机器/拷备份都带上 |
| 3 | `%APPDATA%\noteAll\note.key` | 想给所有项目共用时放这里 |

`note.key` 的内容**就是 key 本身**，一行，不要 JSON、不要引号：

```
sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

程序会自己去掉首尾空白、BOM 和成对引号（记事本保存常带 BOM）。

**`*.key` 和 `.secrets/` 已进 `.gitignore`** —— 别把 key 提交进仓库。

找不到 key 时的报错会列出所有找过的路径，照着放就行：

```
没有找到 API key。按顺序找过：
  ✗ E:\project\cpp_workflow_demo\dist\note.key
  ✗ C:\Users\你\AppData\Roaming\noteAll\note.key
```

## 3. 模型端点（可选）

全部走环境变量，默认值是 DeepSeek：

| 变量 | 默认 |
|---|---|
| `NOTE_LLM_BASE` | `https://api.deepseek.com` |
| `NOTE_LLM_PATH` | `/chat/completions` |
| `NOTE_LLM_MODEL` | `deepseek-chat` |

换成本地 ollama：

```powershell
$env:NOTE_LLM_BASE = "http://127.0.0.1:11434"
$env:NOTE_LLM_PATH = "/v1/chat/completions"
$env:NOTE_LLM_MODEL = "llama3.1"
$env:NOTE_LLM_KEY = "ollama"          # 本地服务随便填，但不能空着
```

`base` 是 `http://` 时程序自动**直连**，不走系统代理（否则本地服务会被代理劫持）。

## 4. 出问题时看哪里

| 现象 | 看什么 |
|---|---|
| 某条记录读不出来 | `<数据文件>.log`（坏行警告、锁超时、保存失败都在这） |
| 草稿一直没生成 | `note show <id>` 看「草稿: failed（已试 N 次：原因）」 |
| 想知道解析成什么 | `note parse "原句"` —— 不写盘，只看结果 |
