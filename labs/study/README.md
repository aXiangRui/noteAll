# 复习资料工作流 —— Phase 0 验证

> 目标：给一堆课件 PPT，自动整理成「大纲 / 知识点 / 考核重点」，输出可自定义样式的 PDF。
>
> 这个目录是**一次性验证脚本**（Python），用来回答一个问题：
> **生成的复习资料值不值得读？**
> 值得 → 再用 C++ 的 Tool 节点实现（产品形态）；不值得 → 及早放弃，省掉两天的 C++ 工程。

## 为什么用 Python

| 环节 | Phase 0 | 产品态 |
|---|---|---|
| 抽 pptx | `python-pptx`（现成） | C++（miniz 解 zip + 扫 XML，约 300–500 行） |
| 生成 | Python + DeepSeek API | C++ `llm` 客户端 + `Llm` 节点 |
| 渲染 | HTML 模板 | 同（模板文件） |
| 出 PDF | Edge `--print-to-pdf` | WebView2 `PrintToPdf`（进程内） |

Phase 0 只验证**质量与结构**，不做产品化。

## 怎么跑

```powershell
$py = "<bundled python>"

# 1. 造一份仿真课件（没有真课件时用）
& $py labs/study/make_sample.py labs/study/out/sample-course.pptx

# 2. 跑整条管道
& $py labs/study/phase0.py labs/study/out/sample-course.pptx labs/study/out
```

产出（都在 `out/`，已 gitignore）：

| 文件 | 是什么 |
|---|---|
| `extracted.json` | 抽取结果：每页 标题 / 要点 / 备注 |
| `material.json` | 模型产出：章 / 大纲 / 知识点 / 考核重点 |
| `review.html` | 渲染结果（改 CSS 就换风格） |
| `review.pdf` | 最终 PDF |

## 实际跑出来的结果（11 页仿真课件）

```
[1/4] 抽取            11 页
[2/4] 生成（调模型）   map 4 次：5 + 6 + 7 + 5 条要点
                      reduce 1 次：合并成 4 章
[3/4] 渲染 HTML
[4/4] 出 PDF          209 KB
```

模型调用 5 次，输入约 6k tokens、输出约 4k tokens ≈ **¥0.01 量级**（DeepSeek）。

生成的结构：

```
1. 进程调度概述与调度目标       第 1-2 页   知识点 5  重点 2
2. 三级调度与基本调度算法       第 3-6 页   知识点 15 重点 3
3. 交互式调度：时间片/优先级/多级 第 7-9 页   知识点 12 重点 3
4. 实时调度与算法选型总结       第 10-11 页 知识点 8  重点 2
```

## 质量评估（这才是 Phase 0 的产出）

**好的地方**

- 抓住了课件里的显式标记：`★ 必考：SJF 平均周转时间最优的证明思路`（p5）、
  `例题 3-2`（p6）—— 正是备注里强调的东西
- 每条知识点都带页码，可以回查
- 每条考核重点都带 `basis`（依据），且只用了允许的三种值
- 全篇重点 5 条都能对应到具体章节，没有凭空发明

**不够好的地方**

- 知识点偏"复述课件"，**跨页归纳弱**（比如"FCFS 的缺点"在 p4，但没和"周转时间计算"关联起来）
- `basis` 区分不严：备注里的话本该是"老师强调"，模型多半标成了"PPT 标记"
- 没有"自测题"（本期没要求，但复习时最有用）

## 两个踩到的真问题（都已修）

1. **一页一章**
   第一次跑出 11 章 = 11 页。原因：prompt 没有规定"按主题合并"。
   加一句「按主题合并成 3–5 章（一页一章是错的）」后变成 4 章。
   > 教训：schema 里写"chapters"，模型就按"页"切；**结构必须在 prompt 里明说**。

2. **Edge 的 `--print-to-pdf` 相对路径**
   Python 里传相对路径，Edge 会解析到**它自己的 cwd**，PDF 无声无息地丢在别处（退出码还是 0）。
   必须传绝对路径（`pdf_path.resolve()`）。

## 真实课件实测：CH02-算法编码工具与算法（145 页 PDF）

用户给的真实课件是 **PDF**（不是 pptx），所以加了 `extract_pdf.py`（pypdf 抽文字层）。
**145 页全部抽到文字，0 空页**，中文正常 —— 说明这份课件不需要 OCR。

### 最终结果

```
抽取      145 页（样板行过滤 0 条 —— 页眉只出现在 7 页，过滤条件不成立）
map       29 次（每 5 页一次，全部命中缓存后重跑只要几秒）
reduce    5 组（4 组 × 36 页 + 1 组收尾）
覆盖      145/145 页，无漏页
产出      13 章 / 131 条知识点 / 14 条考核重点 / PDF 550 KB
```

抓到的"考核重点"举例（都带页码与依据）：

```
AES 四轮操作（字节代换/行移位/列混淆/轮密钥加）          p45-51
3DES 的 EDE 结构与公式 C=E(K3,D(K2,E(K1,P)))              —
ECB 对长信息不安全，暴露重复明文                          p59,61
RSA 加解密与密钥生成 ed≡1(mod Φ(n))、Φ(n)=(p-1)(q-1)      p109,112,115
Diffie-Hellman 计算实例（q=353、本原根 3、K=160）         p127
数字签名性质：不可伪造、真实性、不可变、不可重用          p135
```

### 三个真实撞上的问题（这才是 Phase 0 的价值）

**1. 单次 reduce 被截断**

一次把 145 页的要点喂给模型，输出 16245 字符时被 `max_tokens` 截断，
JSON 从中间断掉 → `json.decoder.JSONDecodeError`。

> 修法：**分层 reduce**。按页段分 4–5 组各自成章，最后用各章的 examFocus（很小）
> 单独挑「全篇重点」。副作用是好的：每组看得少，细节保留更多（知识点 45 → 131 条）。

**2. 章页范围留空档**

模型给出的章页范围漏了 13 页（后来是 1 页），**内容根本没进复习资料**，而它不会报错。

> 修法：① prompt 里明确"必须连续覆盖"；② 代码里做断言（`coverage()`）；
> ③ 仍漏的话用 `repair_coverage()` 并入前一章 —— 确定性修补，不额外调模型。

**3. PDF 里的落单代理项**

pypdf 偶尔返回 UTF-16 残片（`0xD800–0xDFFF`），`json.dumps` 直接崩：

```
UnicodeEncodeError: 'utf-8' codec can't encode characters ... surrogates not allowed
```

> 修法：抽取后清洗掉代理项（`clean()`）。这类字符本来也无法显示，丢掉比替换成 `?` 干净。

### 还剩的不足

- 前几章 `examFocus` 为 0：模型偏向把"重点"留给算法/公式章节，
  概述类章节（p1–36）没有标记 —— 可以要求"每章至少 1 条，没有依据也要说明"
- 13 章偏多（目标 4–8）：分组各自成章时每组都出了 3 章
- 没有自测题（需求里没提，但复习时最有用）
